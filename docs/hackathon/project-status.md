households, and a single public ngrok link serves the demonstration to judges.

## 2. Components

| Component | Files | Status |
|---|---|---|
| **Negotiation protocol library** | `packages/protocol/`: `schema.ts`, `sign.ts`, `thread.ts`; `README.md`, `SPEC.md`, generated `offer.schema.json` | **Complete and published.** Strict schema, Ed25519 signatures, bounded rounds, 10 tests; version `0.1.0`; CI passing in the standalone repository. |
| **Household server** | `src/main.ts` (with `config.ts`, `dates.ts`, `keys.ts`) | **Complete.** Streamable HTTP `/mcp` with bearer authentication; `/peer/offers` with raw-body signature verification; `/api/state` and `/api/reset`; `/sim/*`; passcode protection; fixed demonstration clock (`DEMO_NOW`). |
| **Storage** | `src/db.ts` | **Complete.** One SQLite file per household; a `UNIQUE(thread, delta)` constraint makes commits idempotent. |
| **Demonstration seed data** | `src/seed.ts` | **Complete.** Four households on a fixed clock: the Ahmad Thursday soccer run (the need), the Park Tuesday run and the Chen Sunday swim (tradeable), the Lee household unavailable, the Lee ledger history, and preferences. |
| **Negotiation engine** | `src/engine.ts` | **Complete.** Fan-out ordered by outstanding favours; ranking of unconditional favours against swaps; next-move protocol; collection window; two-sided approval; idempotent commit; expiry sweep; a speakable sentence for every outcome; approval results that retain the proposal terms; late replies revise an earlier "no help yet" outcome into a proposal. |
| **Chooser** | `src/chooser.ts` | **Complete.** `rules` (default) and `claude` (Bedrock, with timeout and rules fallback). Ranks only legal moves generated by the engine. |
| **Peer transport** | `src/peer.ts` | **Complete.** Sealing, logging, delivery, outbox retry, verified receipt and replay protection. |
| **MCP interface** | `src/mcp.ts` | **Complete.** Four tools with output schemas and speakable summaries, and the `ui://` app resource; `respond_to_proposal` returns the proposal terms. |
| **MCP App view** | `web/app/` | **Complete.** Feed, proposal card (Yes and No call `respond_to_proposal`), settlement card and ledger. Rendering uses `textContent` only. |
| **Simulated Alexa+** | `src/sim.ts`, `web/sim/`, `/sim/turn` | **Complete.** A real MCP client connected to the household's own `/mcp`; a device frame hosting the real MCP App through the ext-apps app bridge; transcript, microphone input and speech output, automatic announcement of proposals, calendar, ledger and wire panels, and reset. Paths are base-anchored so that one build serves both `/sim/` and `/<household>/sim/`. |
| **Local runner** | `scripts/dev.ts`, `npm run dev` | **Complete.** Ports 4001 to 4004, shared keys, `--keep` and `PACE_MS`. |
| **Hosting** | `scripts/host.ts`, `scripts/router.ts`, `npm run host` | **Complete and verified.** One public ngrok link with both households served as paths, because a free ngrok account has one reserved domain. |
| **Tests** | `test/` | **Complete.** Protocol, engine, MCP interface, failure drills, four-server end-to-end, the spoken demonstration and two browser suites (`ui.test.ts`, `hosted.test.ts`). |
| **Packaging and documentation** | `README.md`, `.env.example`, `docs/`, `Dockerfile`, CI | **Complete.** The README includes the implementation status table and hosting instructions; the runbook contains the recording script and hosted-testing instructions. |

The core demonstration is verified at four levels: in memory (engine tests), across four
processes over HTTP (end-to-end tests), in a local browser (`ui`) and in a browser through the
public link (`hosted`).

## 5. Decisions

| Decision | Status | Rationale |
|---|---|---|
| **All households run in the Alexa+ simulator** | Implemented | The rules permit simulating Alexa+ in a web application, and development-stage add-ons are visible only to the developer's own account. The project still ships a real MCP server, real tools and a real MCP App, which is what the track assesses. |
| **Bedrock chooser is optional** | Decided | `rules` is the default and the recording configuration; the `claude` path requires one environment variable. |
| **Demonstration device** | Fixed: simulator only | No Echo Show is available; both households are simulated pages. |
| **Hosting through one ngrok link with path routing** | Implemented and verified | A free ngrok account has one reserved domain, and a second tunnel would take it over; `scripts/router.ts` assigns each household a path instead. A named Cloudflare tunnel hostname on a custom domain is an optional upgrade that removes the interstitial. |
| **Private working notes** | Retained privately in `notes/` (excluded from version control) | They may be published at the maintainer's discretion. |

## 8. Risks and contingencies

**Current risks**

| Risk | Mitigation |
|---|---|
| The video is not recorded. | This is the last substantial maintainer task. The runbook removes all open decisions, and the demonstration is covered by tests, so takes should be clean. |
| Judges cannot reach the hosted link. | The machine must remain awake with `npm run host` running. The video and the single-command local setup in the README serve as fallbacks. Every step has been verified live. |
| The ngrok interstitial confuses a judge. | It requires one click and is documented in the testing instructions; command-line requests are unaffected. A Cloudflare hostname on a custom domain removes it entirely. |
| npm publication is delayed. | Both repositories are public regardless; npm publication is supplementary to the submission. |
| A failure occurs during the demonstration. | The failure drills pass (peer offline, replay, tampering, expiry), and the reset button and `/api/reset` restore the seeded state within seconds. |

**Contingency measures, in order of activation** (each is documented in the README if
activated):

1. ~~Real Alexa+ integration~~: removed by decision and replaced by the simulator.
2. Bedrock chooser replaced by the rules chooser *(currently the default)*.
3. ~~Hosting~~: **not required; one ngrok link serving both households is verified.**
4. ~~Direct rendering in place of the ext-apps app-bridge iframe~~: **not required; the bridge
   is implemented and browser-tested.**
5. Voice input and output replaced by typed input *(voice functions; typing is the fallback)*.
6. Proactive announcement of incoming proposals *(functions; tapping is the fallback)*.
7. ~~CI workflow~~: **implemented; both repositories passing.**
8. npm publication replaced by a repository-only Open Source entry.

**Never to be removed:** the two-household approval moment; the offers-only wire log; the
ledger; the tested protocol library; a video under three minutes; the product feedback
(mandatory); and the friction log (bonus). All are implemented.
